# 项目架构说明

## 一、分层图

```
调用方（浏览器 / 测试脚本）
  │  HTTP 请求
  ▼
路由层   service/main.py
  │  调用
  ▼
服务层   service/service.py        ← 待建，逻辑暂时还在 main.py
  │  读写
  ▼
数据层   未接入                     ← /history 现在返回写死的 []
```


## 二、每层职责

**路由层（service/main.py）**
负责：收请求、校验参数、把结果打包回话。
不负责：算答案、存数据。

**服务层（service/service.py，待建）**
负责：算逻辑——拼答案、走判断、以后调 AI 模型。
不负责：收请求（它不知道 HTTP 长什么样）。

**数据层（未接入）**
负责：存和取。
现状：/history 目前返回写死的 []，没有真实存储。

## 三、为什么不都写在 main.py

1. 改动隔离：改 /ask 不会碰坏 /health
2. 能单独测：算答案那步不用起服务器就能验证
3. 换实现只改一处：答案从硬编码换成调 AI，只动服务层
