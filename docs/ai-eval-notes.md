## 一、LLM-as-Judge 的原理与已知偏差

**原理**：用一个 LLM 去理解另一个 LLM 的输出语义，然后给出评价。判分的那一段需要三样输入——题目、被测答案、判分标准（rubric），输出一个结构化结论（例如 `correct` / `reason` / `error_type`）。

**三个已知偏差**：

| 偏差 | 表现 | 触发条件 |
|---|---|---|
| 自我偏好（self-preference） | 判自己同类风格的答案时给高分，答案其实超纲了也觉得「讲得清楚」 | 判分者和答题者是同一个模型 |
| 位置偏差（position bias） | 两个答案对比时偏袒排在前面的那个，交换顺序结论就翻 | 输入里同时出现两个答案 |
| 长度偏差（verbosity） | 越长的答案越容易被判「更好」，即使信息量一样 | 被测答案长度差异大 |

**对策**：自我偏好→判分换一家模型（被测 DeepSeek、判卷智谱/通义）；长度偏差→rubric 里明写「长度不影响评分」；位置偏差→比较类判定跑两遍、交换顺序，不一致就记为判分不稳定。

## 二、为什么语义判断比字符串匹配更适合评测 AI 输出

字符串匹配应对不了表达多样的情况——同一句正确结论可以有无数种写法（「x=2」「解为 x 等于 2」「方程的根是 2」），也扛不住模型爱加铺垫、输出长度不定。必须理解语义才能判得准。

反过来，字符串匹配还有一半代价：它会把**对的判成错的**（假阴性）。而且它只有「过 / 不过」两档，表达不了「步骤对但结论错」「知识点对但讲超纲」这种部分正确。

**结论**：能用明确条件判的，仍然交给规则；语义层面的判断，只能交给另一个模型。

## 三、六个维度的判分方式

| 维度 | 判断方式 | 为什么 |
|---|---|---|
| 知识点正确性 | Judge + 规则辅助 | 关键符号能查（公式、负号位置），讲得对不对得读懂 |
| 步骤一致性 | Judge | 跳不跳步、结论能否由步骤推出，纯语义 |
| 超纲检测 | 规则为主 | 积分号、矩阵、导数、虚数、对数这些能枚举；边界模糊的交 Judge |
| 分层讲解匹配 | Judge | 讲太深还是太浅，只有语义能判 |
| 多轮对话稳定性 | 规则 + Judge | 两次结论比字符串，意思是否矛盾靠语义 |
| 幻觉率 | 规则 + Judge | 编造的定理名能查库（库里没有就是疑似），「听着对其实错」靠 Judge |

**判据一句话**：错误能不能用一条明确的、能写成条件判断的话说清。能，交给规则；不能，交给 Judge。

## 六、判分器自检的第一次观察（2026-11-25）

用 `judges/knowledge.py` 里现成的自检块跑了一次：题目「一个数的 3 倍加 2 等于 8」，标准答案 2，喂进去的答卷是「3x+2=8，3x=6，x=3」。这是第 25 天要留的第一条「踩坑佐证」雏形。

**档位判对了**：`partial` / `final_answer_error`。照维度 1 的档位表，这是「方法正确、最后一步抄错」，判 `partial` 没错。

**理由是错的，而且错两处**：

- **自相矛盾**：理由是「得数正确，但中间步骤 3x=6 的计算错误」——得数其实是错的（3 ≠ 2），前半句先把它说成对
- **指错了位置**：3x=6 这一步本身没错，错在两边除以 3 时应得 2 却写了 3

**怎么理解**：档位能用，`reason` 不能当证据。一条 `pass` 只说明判分器没发现问题，不说明它真检查过。面试里说「我的 Judge 判得很准」，被追问「它凭什么说对」时，现在的答案是空的。

**下一步两个方向**（都还没做）

1. rubric 里加硬要求：`reason` 必须点名答案里的具体一步（哪一行、哪个数），不许复述判分标准。
2. 每次判定附「证据字段」，照不出原文里的关键一句时判 `partial` 而不是 `pass`——判分器说不出理由，本身就是一个信号。

**落盘字段的缺口已经补上**（2026-11-25）：`run_eval.py` 的 `result.append` 里加了 `"answer": replies[-1]`。`results.json` 现在是五个字段：`id / answer / verdict / error_type / reason`。实跑 4 条验证过——五字段齐全，`g7-eq-003` 的 `answer` 收尾正是它的 `\boxed{15}`，没截断、没落空。判分器说「得数正确」，现在能翻出原文核对。

## 七、四条用例连跑三次的稳定性观察（2026-11-25）

用例扩到 4 条之后（新增 `g7-eq-003` 两位数应用题、`g7-eq-004` 同类项指数题），同一批连跑 3 次，共 12 次判定。

**档位是稳的**：12 次全部 `pass`，四条用例的判定一次都没翻。这一层可以下结论、可以对外讲。

**理由不稳，还会串题**：

| 现象 | 证据 |
|---|---|
| 措辞每次都在换 | `g7-eq-002` 第一次是「解题步骤完整，方法正确，得数正确，定理和公式引用正确」，第二次变成「…过程正确…定理和公式使用正确」 |
| 两道不同的题拿到同一句理由 | 第二次运行时 `g7-eq-003` 与 `g7-eq-004` 的 `reason` 一字不差：「得数正确，引用的定理、公式名称也对」 |
| 理由与题目对不上 | `g7-eq-003` 是自编的两位数应用题，通篇没有引用任何定理，却被夸「定理、公式名称也对」 |

**结论**：跟第六节的自检是同一种病——`reason` 在复读 rubric 里的档位定义，不是在描述这份答卷。**档位可信，理由不可信，而且会把 A 题的理由贴到 B 题上。**

这条对面试的价值：它把「Judge 到底保不保真」从一句抽象担忧，变成了可复现的证据——同一个判分器，档位给对了，理由却是模板化的、还串题。第六节那两个改进方向因此有了明确的验收点：改完之后，`g7-eq-003` 与 `g7-eq-004` 的 `reason` 不该再是同一句话。

## 八、第 26 天判分器自测（2026-11-25 — 11-26）

> 草稿区。今天从「三条固定答卷」一路测到「判定能不能稳」，过程按发生顺序记，问题和解法一一对应，等收工再整理成正式小节。

### 8.1 为什么要给判分器喂固定答卷

维度 1 那 4 条用例是被测模型真答的，量的是模型水平。维度 2 这 3 条不一样，带 `canned_reply`（预制答卷），绕过被测模型，专门问判分器「认不认得出这种缺陷」。

道理跟单测一样：判分器也是代码，它判错，上层所有分数就都不可信，而且不会有人察觉。三档各喂一次，`error_type` 映射表那几行才不是死代码。

**两种数据的性质不能混算**：`results.json` 每条要带 `reply_source`（`canned` / `model`），终端分组报数，成绩单只算 `model` 的。否则「7 条全过」看着漂亮，其实一半是判分器自己考自己。

### 8.2 第一轮：`glm-4-flash` 的三条结果

temperature 0，连跑三次结果逐字一致。

| 用例 | 期望 | 实判 | 问题 |
|---|---|---|---|
| sc-001 代换求值（calc） | `partial / skipped_calc_step` | `partial / skipped_calc_step` | 档位对。理由复读档位定义，没点出缺的是 `2a-b=-1 → 3-4a+2b=5` 那一步 |
| sc-002 教室数（word） | `partial / skipped_reasoning_step` | `pass / null` | 判宽了。答卷只写「学生人数不变」，`x+3`、`x-1` 的来历没交代，它当成交代完了 |
| sc-003 新运算（calc） | `fail / unreachable_conclusion` | `fail / calc_slip` | 裁判自己算错：说 `(-x)*(-2)` 应是 `2x`（实为 `-3x-2`），还把 calc 题给了 word 专用的 `error_type` |

### 8.3 加三条 prompt 约束：`glm-4-flash` 纹丝不动

针对上面三个毛病往 prompt 里补了三条（理由必须点出缺哪一步、word 只交代总量守恒不算交代等量关系、判算错时须写出正确结果），重跑：

- sc-001 只从「代入那步没写」改成「从原式跳到结果」——仍是 rubric 原文的复读
- sc-002 一个字没变，理由还是三档定义的拼接
- sc-003 又算错一次，`error_type` 从 `unreachable_conclusion` 串到 `calc_slip`

**判断**：`glm-4-flash` 在「审步骤」「核算术」「按题型选档」三件事上能力不够。错得稳定可复现，说明尺子刻度歪但歪得固定——可以校准，也可以直接换尺子。**改 prompt 不是解，换模型才是。**

### 8.4 换模型的过程：两个新免费模型都调不通，最后靠赠送额度解决

- `glm-4.5-flash` → `429 Too Many Requests`
- `glm-4.7-flash` → 先 `ReadTimeout`，隔 90 秒重试仍 `429`
- 同一时刻 `glm-4-flash` 正常，所以不是网络、不是 key

**转机不在充值，在账号里的赠送资源包**（11-24 生效、12-24 到期）：`glm-5.3-flash` 1500 万 tokens、`glm-5.3-flashx` 300 万 tokens、通用 200 万 tokens。

换 `glm-5.3-flash` 后三条全中档位，而且理由全部点到了具体一步：

- sc-001：指出缺的是「把目标式变形为 `3-2(2a-b)` 再代入 `-1`」
- sc-002：指出没说明「缺 3 间对应 `x+3`」「空 1 间对应 `x-1`」
- sc-003：指出「由 `3x+4=2x` 应解得 `x=-4`，作答却写 `x=4`」

**这一轮的教训记在这里**：判断「必须充值」之前，先看账号里有什么。当时据官方价目表和 429 就下了「只能充值」的结论，实际额度前天刚发到账上。

### 8.5 判据本身有两个洞（由这轮实测暴露）

**洞一：`fail` 的两档有交集。**

`contradiction`（前后矛盾）与 `unreachable_conclusion`（推不出）不是互斥的两个类，同一份答卷可以同时像两边。sc-003 就是：写了 `3x+4` 又写「所以 x=4」，像矛盾；中间没写 `3x+4=2x`，像推不出。判分器挑哪个都讲得通。

**解法**：改成有先后顺序的判定，并划一条硬线——

1. 先查答卷内部是否自相矛盾（它自己写出的算式之间、或算式与它给出的结论之间对不上）→ `contradiction`
2. 内部不矛盾，只是缺了关键步骤、结论无法由已写出的内容推出 → `unreachable_conclusion`
3. 硬线：**矛盾若必须借助题面条件才能看出来，不算内部矛盾，按第 2 条判**

顺序不能倒——先查「推不出」会把真正自相矛盾的答卷一律归到第 2 条，`contradiction` 就永远触发不了。

落地：`docs/eval-dimensions.md` 维度 2「按题型分档」一节新增「`fail` 的两档怎么分（仅 `calc`）」；`step_consistency.py` 的映射表同步改成 ①②。

**洞二：`word` 的 `fail` 标签两处写得不一样。**

prompt 写 `word 判 fail → null`，判据文档写 `contradiction` / `unreachable_conclusion`。同一件事两种说法，模型照前者干活、人看后者困惑。

**定案**：统一成 `null`。理由是 word 的 fail 只有「建错」与「链断」两种，都塞不进那两个标签——建错是跟题意打架，不是跟自己打架；链断是顺序错了，不一定是少写步骤。信息不丢，交给 `reason` 说清是哪一种。

### 8.6 第三轮：顺序规则生效，但 sc-001 翻了

- sc-002 `partial / skipped_reasoning_step` ✓，10.5 秒
- sc-003 `fail / unreachable_conclusion` ✓，81 秒——顺序规则生效的直接证据
- sc-001 **从 `partial` 翻成 `pass`**，34 秒

sc-001 翻车的理由暴露了根因：

> 「后续按其所述把该式代入目标式，可核验 3-4a+2b=3-2×(-1)=5，各步衔接得上」

它在**替答卷把没写的步骤补上了**，补完觉得衔接得上，就放过。而维度 2 要判的是答卷**写了什么**，不是它**心里可能懂什么**。

**解法**：加一条硬约束——

> 只判答卷实际写出的内容。答卷没写的步骤，不许替它补，也不许假定「它其实懂，只是没写」。缺了就是缺了；要核验某个算式，也只能核验答卷里已经出现的那几行。

这条是整个维度 2 的地基，比任何档位描述都重要。

### 8.7 两个工程问题

**耗时不稳定**：三条实测 10.5 / 34 / 81 秒。越需要它自己解题的答卷越慢——sc-003 要它自己解 `3x+4=2x` 得 `-4`，所以最慢。**慢是「它在算」的证据**：`glm-4-flash` 两三秒就出结果，因为它根本没算。

后果：`llm_client.py` 原来 `timeout=30` 会把 81 秒那条直接掐断，已改 `timeout=120`。

**判定不稳定**：同一模型、同一 prompt、同一答卷，sc-001 在不同轮次给出相反档位。这属于 LLM-as-judge 的已知问题，不是这次改坏的。若加完「不许补步骤」仍会翻，就上「同一条跑三遍取多数」——有实证支持（criteria 注入 + 集成投票是提准最有效的两个手段，且便宜模型从投票里获益更大）。

### 8.8 换模型后的回归：串题消失、固定答卷闭环（2026-11-26）

裁判换成 `glm-5.3-flash` 之后，先跑维度 1 那四条做回归：4/4 全 `pass`，四条理由各不相同，且都能落到具体步骤上。

对照第七节记的「`g7-eq-003` 与 `g7-eq-004` 拿到一字不差的同一句理由」——这个串题现象消失了。

**这是换模型的第二个收益。**第一个是档位准确率（8.4），第二个是理由不再模板化、不再把 A 题的理由贴到 B 题上。后者对面试更值钱：第七节里「Judge 到底保不保真」只有反面证据，现在有了正面的一条——同一个判分器，四道不同的题，四句不同的、都能指到具体步骤的理由。

同一天，三条固定答卷走 `run_eval` 真正闭环（接入 `canned_reply` 分支后），判定全部落在期望档位。当时 `sc-004` 还没加，所以表里是三条：

| 用例 | 期望 | 实判 |
|---|---|---|
| sc-001 | `partial / skipped_calc_step` | ✓ |
| sc-002 | `partial / skipped_reasoning_step` | ✓ |
| sc-003 | `fail / unreachable_conclusion` | ✓ |

终端报的是「3 条用例，0 条通过」。「0 条通过」在这里不是失败，而是三条缺陷全被按预期抓到。但这暴露了统计口径的问题：只用单一的「通过率」呈现，一旦混进自测用例必然误导。等 `reply_source` 分组统计接上再解决。

### 8.9 排版对照的意外结论：结构清晰反而判得更严（2026-11-26）

第 4 块加了 `sc-004`：和 `sc-001` 同一道题、同一处缺陷（都不写 `3-2(2a-b)` 这个变形，只用「整体代入」带过），唯一差别是排版——分步编号、分行、`∴`、加粗。

**原假设是：「美化排版会让裁判看着舒服，从而判宽。」实测方向相反。**

四条跑两遍，结果稳定：

| 用例 | 形态 | 第一遍 | 第二遍 |
|---|---|---|---|
| sc-001 | 一段连写，无分步 | `pass` ✗ | `pass` ✗ |
| sc-002 | 一段连写 | `partial` ✓ | `partial` ✓ |
| sc-003 | 一段连写 | `fail / unreachable_conclusion` ✓ | 同 ✓ |
| sc-004 | 分步编号 + 分行 | `partial` ✓ | `partial` ✓ |

sc-001 两次都判 `pass`，理由都是「代入目标式（即 3-2(2a-b)=3-2(-1)=5）得到 5」。答卷没有这行，裁判每次自己补。**两次一致，写明是稳定错，不是漂移。**

而 sc-004 两次都判 `partial`，理由都点出「缺 3-2(2a-b) 变形」。

**同一处缺陷，一条稳定判对，一条稳定判错，差别只在答卷形态。** 机理：

- 分步编号 → 裁判有锚点，可以逐条对账，缺哪步指哪步；
- 压缩连写 → 裁判读成一个完整意图，而不是一笔可查的账，于是自动脑补中间步骤。

所以这条不是「格式偏见」的常规形态（美化加分），而是**结构化给裁判提供了审计锚点，反而判得更严**。

**顺带否掉一个方案**：多跑取多数治不了这个，稳定错跑三遍还是三遍 `pass`，只能改 prompt。具体改法与验收见 8.10。

### 8.10 两处改动与验收：逃生口比拆条规则更关键（2026-11-26）

8.9 判断「要改 prompt」，实际落了两处改动，其中第二处才是关键。

**改动一：加拆条规则。** 在「只判答卷实际写出的内容」之后加一条——压缩成一句连续叙述的答卷，必须先拆成它隐含的最小步骤序列再逐条对照；每个变形/代入必须在这句话里显式出现才算写出；「代进某式」「算得」「即得」「由此得」后面直接跟结果、中间没有式子，一律算缺步。

**改动二（关键）：堵掉第 36 行的逃生口。** 原来那条是：

> 只有一句话但结论正确、过程确实不需要展开的（例如直接写出因式分解结果），可以判 pass。

`sc-001` 的答卷正好是「只有一句话、结论正确」的形态，**这条给了裁判一条合乎规则的放行通道**。所以问题不只是「它想替答卷补步骤」，还有「它手里有一条允许从宽判定的条款可援引」。改后收紧为「整题只需一步计算、且这一步本身不可再分」，并写明「凡题目需要两个及以上变形动作的，压缩成一句一律按拆条规则核对，不许用本条放行」。

**这修正了 8.9 的一个判断。** 8.9 把两次 `pass` 全部归因于「脑补步骤」。加上拆条规则之后仍然可能判 `pass`，因为逃生口还在。**约束打架时模型永远选宽的那条**——这是这次最值钱的一条经验，比拆条规则本身可迁移。

**验收（各跑两遍，两遍完全一致）**：

| 用例 | 期望 | 第一遍 | 第二遍 |
|---|---|---|---|
| sc-001 | `partial / skipped_calc_step` | ✓ | ✓ |
| sc-002 | `partial / skipped_reasoning_step` | ✓ | ✓ |
| sc-003 | `fail / unreachable_conclusion` | ✓ | ✓ |
| sc-004 | `partial / skipped_calc_step` | ✓ | ✓ |

终端报「4 条用例，0 条通过」——`0 pass` 正是期望值，四条本该全都不通过。

`sc-001` 两遍的理由措辞不同、指向同一步（都点名「算得」这个黑箱动词后直接跟结果），说明裁判是真在核对，不是背下来的。`sc-004` 两遍都判 `partial`，正式确立为常驻回归用例——它证明「排版工整不加分」这条规矩守住了。
